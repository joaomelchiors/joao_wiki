# MCP

Pessoal, nós vamos agora falar de uma sigla que representa a terceira ferramenta que a gente vai apresentar para você. Eu já falei de skill e já falei de outra sigla complicada, mas que não é tão difícil de entender, que é o Spec-Driven Development, o desenvolvimento dirigido, orientado por especificação, que a gente viu de uma forma mais resumida. Eu mostrei para vocês a ideia dos passos, certo? Existem outros aspectos que a gente vai ver ao longo dos projetos, mas, por ora, aqueles passos são suficientes para entendermos como funciona a mecânica.

E agora a gente vai entender essa terceira sigla, chamada MCP. MCP significa Model Context Protocol, que, traduzido para o português, lendo de trás para frente, seria Protocolo de Contexto do Modelo, certo? O Protocolo de Contexto do Modelo é exatamente um padrão de comunicação entre o modelo de inteligência artificial e o mundo exterior: as aplicações, a internet, os sistemas da empresa. Em outras palavras, é uma forma de o modelo acessar algo que está fora dele. E, para isso, criou-se o que a gente chama de protocolo.

O que é um protocolo? É uma maneira de se portar ou de se comunicar. Por exemplo, se você vai a uma reunião na ONU, existe um protocolo de como você deve agir naquela reunião. Se você tem no seu bairro uma sociedade secreta com seus amigos, existe um protocolo de como bater na porta da sede da sociedade secreta e falar uma senha secreta. Existe uma maneira de se comunicar.

Então, de uma forma didática, a gente pode dizer que o MCP é como se fosse uma tomada padrão que faz com que a IA se conecte com o mundo exterior. Quando a gente pensa em tomada, pensa logo neste desenho aqui, né? Uma tomada na parede e um plugue que você quer conectar nessa tomada. No desenho que foi feito aqui, o plugue parece ser redondo e o encaixe parece ser retinho, como se fosse uma reta. Ou seja, esse plugue é incompatível com essa tomada, tá? Se você não estabelece um protocolo correto, na hora de conectar não vai funcionar.

O que o MCP entrega para a gente? Ele entrega uma forma padronizada de a IA se conectar com o mundo exterior. E, se o time de engenharia cria um MCP (vamos começar a chamá-lo de conector), você tem a IA, coloca um conector e essa IA passa a conseguir se conectar com a aplicação. Se você tem um conector do Google Drive, a IA passa a se conectar com o Google Drive através desse conector. Pode haver um conector que faz com que a IA se conecte com a aplicação da sua empresa. E esses conectores são padronizados.

Quem criou o MCP foi a Anthropic, a empresa do Claude, e ele virou um padrão de mercado. As outras empresas se adaptaram a essa criação da Anthropic. Então é um padrão de conexão. É como se a IA agora passasse a conseguir se conectar com o seu sistema, fazer consultas a ele e obter dados dele, com a própria IA fazendo isso diretamente. E, a partir daí, ela consegue executar tarefas com mais poder, exatamente porque tem acesso a mais contexto. Por isso o nome é Protocolo de Contexto do Modelo. É como se você estivesse dando à IA uma forma de se conectar com novos contextos que estão fora dela, para que ela possa, dentro desses novos contextos, executar tarefas mais poderosas.

Então esse protocolo permite ligar agentes de IA a ferramentas e dados externos. Como ferramentas, você pode pensar no Gmail, no Google Drive, no Canva e em várias outras ferramentas de mercado. Já os dados externos podem ser um banco de dados da sua empresa, um sistema da sua empresa e assim por diante. Claro, é sempre preciso ter cuidado e fazer essas conexões de forma segura, principalmente quando você lida com o banco de dados de uma empresa ou algo do gênero. Mas a ferramenta está aí para a gente usar e extrair o melhor dela, tá?

O MCP funciona como uma interface. Interface é basicamente como o formato da tomada na parede, por exemplo. Ela tem uma forma geométrica que exige que você crie uma forma compatível para encaixar. Então essa interface, essa forma padronizada, faz com que as empresas se adaptem e construam MCPs que atendam a essa necessidade.

E como isso funciona? Você tem aqui a IA. Ela vai falar com esse conector, com esse MCP, e esse conector vai falar com a aplicação. Ou seja, a IA não precisa entender como o YouTube funciona, nem precisa se adaptar ao Gmail ou ao Google Drive, cada um com uma forma diferente de se comunicar. É como se a IA falasse inglês e a ferramenta falasse alemão, e o conector fosse capaz de traduzir do inglês para o alemão e do alemão para o inglês. Ele funciona como um tradutor intermediário.

Então, você tem aqui o agente de IA, e ele fala com o MCP, que é como se fosse um tradutor. O agente passa um comando para o MCP, e o MCP traduz esse comando para o YouTube. O YouTube devolve a resposta, o MCP traduz essa resposta e a envia para o agente de IA. Então o MCP é esse meio do caminho para se conectar de uma forma padronizada com qualquer tipo de aplicação de mercado: planilhas, calendário, o CRM da empresa em que você trabalha, um ERP que você usa na sua empresa, um banco de dados que você usa no seu trabalho ou na sua aplicação, o Google Drive, o Gmail, o YouTube e dezenas e dezenas de outras aplicações com as quais você pode se comunicar usando essa estratégia.

A ideia é: uma vez que você tem um MCP, o agente vai sempre conversar de forma padronizada com ele, e o MCP vai entender como funciona cada uma dessas aplicações. Isso significa que, para cada aplicação, você tem um conector específico. Você tem um MCP do YouTube, um MCP do Gmail, um MCP do Google Drive, um do banco de dados, um do ERP e assim por diante.

E esses MCPs podem ser construídos dentro do seu projeto. Lembra que a gente tem lá um projeto, uma pasta onde ficam os nossos scripts? A gente pode criar uma pasta para os conectores. Não existe um padrão: você pode criar a pasta com o nome que quiser, como “mcps” ou “conectores”, e colocar esses conectores lá dentro. Para criar um MCP, é usada linguagem de programação, e existe uma lógica interna de como as coisas funcionam. Eu não vou falar sobre essa lógica aqui nem sobre linguagem de programação. Você não precisa entender como o MCP funciona internamente. Você precisa entender para que ele serve, que é exatamente fazer essa conexão, tá?

E por que ele é importante? Porque ele padroniza as integrações com o mundo exterior, certo? E o nome desse padrão, que é importante você saber, é MCP, porque, quando você for pedir para a IA gerar um, você vai dizer: “Quero que você gere um MCP que tenha o objetivo de acessar os dados externos assim, assim e assado”, tá?

Ele evita criar uma conexão diferente para cada ferramenta. Ou seja, a IA sempre se conecta da mesma forma, e os conectores é que sabem falar com essas aplicações. Do ponto de vista da IA, a forma de se conectar e de se comunicar é sempre a mesma. E o agente tem uma lista de conectores ativos, então ele sabe qual usar. Se você está pedindo para acessar um e-mail do Gmail, ele vai usar o conector certo e obter essa informação para você de uma forma muito interessante, certo? O MCP também facilita o reaproveitamento dos mesmos conectores em vários projetos diferentes, porque é um padrão de mercado, tá? E vai te dar mais organização e controle para acessar o mundo exterior, né?

Cada conector expõe ações. A ação de ler um e-mail tem a ver com o conector do Gmail; uma ação de acessar um vídeo do YouTube tem a ver com o conector do YouTube; uma ação para salvar um arquivo no Google Drive é uma ação específica daquele conector. Então cada conector tem suas ações e aquilo que ele permite fazer. É o conector que vai dizer o que você pode fazer dentro daquele cenário.

Por exemplo, lembra que a gente estava trabalhando com arquivos locais? Usando um conector do Google Drive, a gente pode dizer: “Salve um arquivo na pasta do Google Drive”, “salve um arquivo desta forma”, “leia este arquivo”, “altere o arquivo”. Você consegue acessar arquivos na nuvem através de um conector, por exemplo, do Google Drive, certo?

Alguns exemplos práticos: “Eu quero ler e resumir um e-mail.” Você vai ter essas opções de leitura de e-mail através do conector de e-mail. “Eu quero que você busque um arquivo e organize uma pasta.” Isso se faz através de um conector do Google Drive. “Eu quero consultar vídeos, ler as descrições e os comentários do YouTube.” Se você vai criar um agente para automatizar as respostas no YouTube, por exemplo, pode usar um conector do YouTube e fazer todo o trabalho de curtir comentários e responder usuários de forma automática, através desses conectores. Sem isso, você não teria essa capacidade, ou pelo menos seria muito mais difícil fazer ações como essas. Você também pode, por exemplo, atualizar dados de uma planilha no Google Sheets através de um MCP, um conector que te dá acesso a esses documentos na nuvem.

E, no final, o resultado é que a IA vai conseguir agir, porque o nosso grande objetivo com os agentes de IA é agir, é ter ação, é realmente fazer o trabalho no nosso lugar. Ela vai conseguir agir fora do chat. Ou seja, quando a gente quer fazer uma ação no Canva para gerar um slide, ou no Notion para gerar um documento ou organizar alguma coisa, a gente pode usar um MCP que vai dar uma série de permissões e funcionalidades. E, através dessas funcionalidades, você vai conseguir fazer trabalho real, trabalho fora do chat. Não é simplesmente texto gerando texto: é você, através dos seus comandos, gerar trabalho real, mover arquivos, criar arquivos, criar documentos reais dentro das aplicações de mercado que a gente usa.

Fora que você pode fazer isso dentro dos sistemas da sua empresa. Você pode criar, através de MCPs, integrações entre sistemas que não se conversam. Você tem um MCP que conecta com o sistema A e outro que conecta com o sistema B, e esses sistemas não conversam entre si. Você faz um processo no meio de campo que cuida de todo o processamento e, no final, consegue uma integração que, por exemplo, nem existia. Tudo isso é possível fazer com os MCPs, tá?

E qual é a ideia principal do MCP? O MCP não é a tarefa em si, certo? O MCP é um conector, um meio de campo, um intermediário, né, que permite conectar a IA a qualquer ferramenta de que você precise para fazer uma determinada atividade. E as ferramentas são as mais diversas possíveis, tá? Existem muitas ferramentas incríveis no mercado, e o trabalho do MCP é exatamente ser esse meio de campo, o conector entre o agente de IA e a ferramenta certa para aquele trabalho, tá bom?

Então, dado esse contexto do que significa um MCP, na próxima aula a gente vai começar a trabalhar com os nossos MCPs.
