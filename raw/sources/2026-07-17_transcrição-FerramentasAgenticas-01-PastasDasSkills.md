# Transcrição Ferramentas Agenticas - Pastas das Skills

Pessoal, eu queria comentar com vocês. A gente já falou um pouquinho da interface ali muito rápido, a gente já instalou as ferramentas, a gente vai focar mais precisamente nos conceitos. Eu vou pegar essa ferramenta aqui do Cloud Code e colocar desse lado e o Visual Studio Code do outro, para que a gente possa falar de alguns conceitos importantes. Qualquer coisa, a gente pode criar aqui uma nova sessão para trabalhar com o Cloud Code. Eu não vou ficar mostrando absolutamente tudo no Codex e tudo no Cloud Code, porque durante o curso a gente vai usar essas ferramentas e você vai perceber que elas são muito parecidas, né? Claro que tem algumas coisas diferentes umas das outras, mas que no final você vai conseguir usar as duas de forma bem tranquila. Vamos lá. Quando a gente... Um dos pilares, e eu queria usar essa aula aqui como um pilar importante para o curso inteiro, tá, é a ideia de skills. Eu já estou assumindo que você lida com o trabalho com IA, que você sabe o que é um prompt, que você sabe como interagir com inteligência artificial, porque isso aqui não é um curso para quem realmente está zerado, né? Se você tá, chegou aqui absolutamente zerado, você não é um desenvolvedor, tá? Então esse curso provavelmente você vai ter dificuldade, principalmente quando a gente for mais lá pra frente. De qualquer forma, dentro do Cloud Code e do Codex, a gente vai usar umas pastas especiais que são pastas que ele consegue olhar nessas pastas e extrair informações importantes. No caso do Cloud Code, a pasta que ele vai usar é a pasta .cloud. A pasta .cloud, começando com ponto, historicamente essa pasta é uma pasta escondida. Toda pasta que começa com ponto dentro do Linux, dentro do macOS, são pastas escondidas, certo? E isso é um conceito que alguns alunos devem provavelmente já ter perguntado sobre isso. Mas é um conceito importante você entender. No Visual Studio Code essas pastas vão aparecer aqui por padrão, tá? Mas dependendo de qual sistema operacional você esteja usando, se você abrir a pasta, você não vai ver essa pasta disponível pra você. Se a gente entrar aqui no AI Driven Development, na parte de exemplos, intro, a pasta .cloud do Windows, ela aparece. Então, o Windows não tem esse mesmo padrão, digamos assim, de nomenclatura de pastas começando com ponto, com pastas escondidas. Mas o macOS existe e no Linux também. Então, se você tiver nesses dois sistemas, provavelmente essa pasta não vai aparecer. Se você estiver usando o Codex, tá? O nome da pasta é agents, tá? Porque aqui ele vai usar essa pasta .agents pra colocar ali algumas configurações que essas ferramentas irão usar. Dentro do Cloud Code, quando você tem um conceito que é quase que um pilar, quase que a base de boa parte daquilo que a gente vai construir de desenvolvimento de software com arquitetura de verdade, eu diria que a maior base que nós temos é a skill, a habilidade. E as skills são armazenadas dentro do Cloud na pasta skills, tá? E no Cloud Code a pasta também é chamada de skills. Então, se você quiser usar uma estratégia de link, link simbólico que existe nos sistemas operacionais, você pode ter uma pasta só e eventualmente você fazer com que uma pasta aponte para outra, e você conseguir trabalhar tanto com o Cloud Code como com o Codex, usando essas pastas distintas. O que é que eu vou fazer aqui? Eu vou criar um exemplo que eu vou falar sobre skills, sobre esse conceito que é importantíssimo. Nós vamos criar uma skill na mão, nós vamos desenvolver uma skill do zero, que é algo que a gente não vai fazer de forma muito recorrente dentro do curso, porque a gente vai acabar criando as skills através de inteligência artificial. Mas eu quero criar a skill do zero para te mostrar como que funciona, e depois a gente vai interagir com a ideia de Spec Driven e também vamos falar um pouquinho de harness, né? Alguns conceitos que vão ser levados para o curso inteiro. Nós vamos trabalhar aqui dentro desse curso. Então, já que eu falei um pouquinho das pastas, essas pastas têm uma padronização, essas pastas são importantes. Léo, essas pastas ficam dentro do meu projeto? Muito provavelmente sim. Você vai colocar lá essa pasta dentro do teu projeto e ela vai conviver dentro do código-fonte da tua aplicação. Se você eventualmente tem múltiplas aplicações diferentes em lugares distintos e você quer pegar as suas skills e jogar isso dentro de uma área distinta, você pode sim trabalhar com o repositório do Git, se você é um dev sabe disso, ter um repositório do Git separado e usa a ideia de submodules. Não é o que eu vou entrar no detalhe agora, só uma única coisa que eu estou mostrando para vocês é essas duas pastas são pastas onde nós vamos habilitar ou armazenar, melhor dizendo, as nossas skills. E na próxima aula eu quero te falar de um exemplo de skills e mais do que isso, nós vamos construir uma skill que depois a gente vai interagir com você, tá bom? Para você entender de forma muito clara o que é que significa uma skill, para que ela serve e por que ela vai mudar de forma profunda tudo aquilo que você vai fazer daqui para frente. Então eu quis só criar as duas pastas, uma pasta será lida pelo Codex e a outra pasta será lida pelo Cloud Code. Então na próxima aula vamos falar sobre skills.
