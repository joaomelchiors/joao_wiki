# Transcrição Agents, Skill & Eng. de Contexto - Rule vs Skill


Então nós vamos usar agora nessa aula super rápida, conceituar o que é Rule e o que é Skill. Vou colocar tudo numa aula só pra gente confrontar um pouco as ideias. O mais importante não é a ferramenta que você usa de forma deliberada para suportar esses conceitos. São conceitos que estão para além das ferramentas. Eu vou mostrar uma ferramenta específica, que é um conceito que suporta claramente, de forma explícita, esses dois conceitos. Mas não quer dizer que a sua ferramenta igual de Code, Codex e outras ferramentas vão suportar exatamente os mesmos recursos com os mesmos nomes, tá? Então eu quero falar sobre Rules e Skills. Eu vou copiar aqui os conceitos que foram gerados pelo Claude Code e tirar minhas outras elas. Depois de eu dizer pra ele que eu tinha feito uma coisa errada e aí ele corrigiu aqui a definição, tá? Então cuidado na hora de dizer pra AI a usar, digamos assim, uma definição, né? Ter certeza que ela colocou de forma certa, porque às vezes ela exagera aí no tipo de definição que ela usa na prática. Então vamos lá, tá aqui a definição de Rule, tá? Então é o seguinte, uma Rule, uma regra, é uma convenção ou uma restrição que o agente deve respeitar quando o contexto for relevante. Às vezes você tem uma regra que é usada em praticamente em toda a tua aplicação. Você pode existir regras nesse modelo que ele tipo usa isso no teu projeto inteiro. Mas muitas das vezes, né, várias vezes ele não vai aplicar aquela regra dentro de determinado contexto, tá? Então sempre que for relevante, não é necessariamente global uma regra de nomenclatura de entidades, que é o que a gente vai fazer de exemplo. Só se aplica quando você está criando ou modificando entidades. O que define uma Rule não é a sua abrangência, mas sim que ela é declarativa. e descrever o processo. Então ela foca muito mais nessas restrições, nessas regras, sem necessariamente definir como que um determinado padrão é aplicado, como que um determinado processo é construído. Então, uma regra vai mais nesse sentido, né, de estabelecer algumas restrições e algumas lógicas aí para a sua aplicação. A outra, outro conceito que eu quero colocar aqui do outro lado, já vou pegar aqui o conceito de skill para a gente ler e conversar sobre ele, é o seguinte, eu vou copiar aqui. É, tem aqui ó, skill, ela tem uma capacidade de executar uma tarefa complexa de ponta a ponta, pode ser uma tarefa simples também, não necessariamente complexa, seguindo um processo definido e ordenado. Ela é ativa, ela descreve como fazer algo passo a passo. Internamente, uma skill sabe quais são as boas relevantes para aquela tarefa e as aplica automaticamente. Então, mesmo que você não tenha dentro da sua ferramenta o conceito de skill especificamente explícito, dentro da tua skill, você pode referenciar uma regra. Então, se você tem uma regra de nomenclatura que os arquivos devem ser seguidos de uma determinada ordem, é de uma determinada ordem não, de um determinado padrão de nomenclatura, e você faz uma skill que se opera em cima, essa UX de nomenclatura para que todo, toda a skill que for, toda a lógica que for executada nessa skill, use a nomenclatura que foi definida lá naquela regra. Isso pode ser feito independente de sendo pulsou um antigravity ou Cláudio Code, Codex. E uma das coisas que eu queria que vocês prestassem atenção aqui nesse nosso curso, eu vou até colocar em tela cheia aqui, é gente, não fique focado especificamente em uma determinada IA. Eu vou mostrar umas ferramentas que eu uso. Vou colocar outras ferramentas que eu uso um pouco menos, mas independente do que você usar, tem gente que usa o Cursor. Tem gente que usa o Antigravity, tem gente que digita lá e elimina as palavras, né? Tem pessoas que usam o Codex, tem gente que usa o Cláudio Code. Então, não importa a IA que você vai usar. Os conceitos estão lá. O que é uma habilidade? Nada mais é do que uma manipulação do contexto. Nada mais é do que você colocar no topo do contexto uma descrição e um markdown com o fillshot, né, com a ideia de exemplos de código, que também é um ponto muito importante quando a gente fala de engenharia de prompt, né? Quando você cria uma estrutura de um prompt, você pode usar aquela técnica fillshot. Fillshot é a técnica que você tem para colocar exemplos de código dentro do seu pedido. Então tá aqui, olha, como é que eu crio uma entidade? Tá aqui um exemplo de como se cria uma entidade. E aí você coloca dentro dos prompts aquele exemplo ou dentro da skill aquele exemplo e ele sabe exatamente como que cria uma entidade, porque tem exemplos que ele pode seguir. Então essa é a ideia de você ter uma skill. Ela pode referenciar uma rule, um outro arquivo markdown, independente se o Cláudio Code suporta rule, independente do Codex se suporta rule, independente da ferramenta que você está usando ter ou não esse conceito de forma explícita. O Cursor tem o conceito de rule implícito, e o conceito de skill explícito. Então a gente consegue de forma explícita criar os dois e mostrar pra você como que isso é criado. Mas não fica tão preso na ideia da ferramenta. Você vai conseguir ter os mesmos resultados usando o Cursor, você vai ter os mesmos resultados usando o Cláudio Code, usando o Codex. Claro que cada um vai ter umas variações, mas quanto mais contexto você der, mais associadas vão fazer exatamente aquilo que você pediu. Então, eu queria falar sobre esses dois conceitos pra você entender. Mas eu queria que você entendesse que mais importante do que a ferramenta, mais importante do que ter lá um símbolo que invoca uma rule dentro da sua ferramenta, que você entenda o conceito por trás, que é uma restrição, uma convenção, e algo que vai ser aplicado dentro de uma determinada contexto, mais como regras passivas que vão ajudar ali a tua skill na hora do processamento respeitar essas regras que precisam ser feitas. E a skill já é um processo mais ativo, é uma habilidade que ela tem de construir algo dentro da tua aplicação, seguindo um padrão que você estabeleceu dentro da skill. Então, na próxima aula, nós vamos criar uma rule e depois nós vamos criar uma skill e eu vou mostrar pra vocês como que isso é feito na prática, através de um exemplo, que nesse momento vai ser um exemplo descartável. Eu não vou querer manter esse exemplo, porque não vai ser um projeto ainda, mas eu quero só mostrar pra vocês aí como que esses dois elementos se relacionam entre si e como que a gente pode usar skills e rules na prática. Tem um exemplo de brinquedo, mas depois a gente vai fazer exercício mais sério logo na sequência.
